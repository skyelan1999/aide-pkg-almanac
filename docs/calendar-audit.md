# 历法审计 · 2026-10-21

逐日比较1901–2099年72,684天，独立参考为香港天文台公开公农历对照表，另获取2100年作尾部月份/节气上下文。200个原始文件的SHA-256在vendor/hko-reference.json中；完整逐日事实夹具在test/hko-days.json.gz，原引擎结果在calendar-audit-baseline.json。不是用库自己的输出生成预期值。

- lunar-javascript 1.7.7：30天农历与HKO表不同，集中2057-09-28起的一个月。HKO已提示2057年此朔临近午夜存在一日不确定性，因此称“来源差异”，不声称已证明该天文算法一定错误。
- Node v24.19.0 / ICU 78.3：447天农历不同，涉及1917、1922、1954、1955、1987、1999、2012、2018、2027、2030、2057、2070年。不能据此断言所有ICU版本都有相同差异。
- 节气：6次日期相差一天（12条逐日标签差异），涉及1912小雪、1913秋分、1917大雪、1927白露、1928夏至、1979大寒。跨午夜时刻对日期判断敏感；未用任意秒数去补偿。

实现采用固定HKO月份锚点和节气日期；保留未修改的lunar-javascript原件（仅黄历使用）处理估算时刻/民俗表。农历与生肖以正月初一换年，黄历干支年月以节气所在日切换。节气时刻仍是算法估算；若计算落日与官方日期不同，time为null，保留computedTime/computedDate，并提供提示。

首个不完整月份1901-01-01的月份锚点按1901历表后续十二月序列恢复，并与两引擎交叉检查；HKO即时API不提供该日，未伪造API验证。HKO自身对远期接近午夜的朔和节气有不确定性说明，未来应按新公布资料复核。固定历表不等于给原算法做了数学正确性证明，也不代表政府认证。

另外修复错误参数被农历/时间插件静默当作“今天”的问题，明确拒绝空值和错误类型。时间插件区分主机系统时钟与SSH设备时钟，不宣称已做NTP校准。

运行：`node test/calendar-audit.test.cjs`（72,684日离线核对）；黄历另运行 `node test/almanac.test.cjs`。来源：https://www.hko.gov.hk/tc/gts/time/conversion.htm 。官方规则参考GB/T 33661—2017《农历的编算和颁行》。
